Reference · EventBridge-first · domain-owned · catalog-driven · eu-west-1

One catalog, one hop, one bucket pair per domain

Each domain account owns its EventBridge Classic bus, its services and its REST API. The platform account owns one central Custom Event Bus, the archive into bronze and silver, API auth and the nightly checks. EventCatalog is the source of truth for events and APIs, and a generator writes every account's infrastructure from it. PII travels classified: pseudonymous ids in clear, direct identifiers encrypted per subject, special categories never.

The shape

Two domains are shown; every domain account has the same shape. Solid arrows carry events, the amber arrow is the only bus-to-bus hop EventBridge allows, dashed arrows are subscribers delivering into a queue the consumer owns, and the dotted teal arrows are the generator writing infrastructure into each account.

Why there is no fan-out

The first design (ADR-001) forwarded public events from central back onto every other domain's bus. EventBridge Classic delivers one bus-to-bus hop per event: in a real account the second hop is refused with THIRD_ACCOUNT_HOP_DETECTED and the event lands in the fan-out rule's DLQ. LocalStack delivers the chain anyway, which is why that mechanism is sandbox-only. ADR-021 replaces the second hop with a subscriber on a Custom Event Bus.

What the Custom Event Bus gives natively

  • Consumer-owned subscriptions: filter, one target, delivery role, retry policy, DLQ, created in the consuming account
  • Retention and point-in-time replay by subscriber start position
  • FIFO per EventGroupId (the relay sets it to aggregateId)
  • Publish-time deduplication on DeduplicationId = eventId inside a 5-minute window
  • Loop detection, best-effort, with LOOP_DETECTED in the DLQ

What it costs

  • Billed per GB published, delivered and retained, not per event
  • No LocalStack emulation: subscriber behaviour is sandbox-only; platform-local renders the same subscriber file as a Classic rule on a stub central
  • No London endpoint: the whole platform runs in eu-west-1
  • One subscriber change at a time per bus; six create-only properties, so a target change is add-then-remove

The catalog is the only control plane

Every rule, subscriber, bucket, route, client, alarm, role and data contract is a deterministic function of the catalog. Drift is caught twice: once between the catalog and its generated output, once between the generated output and what is applied. Spike C proved that a catalog edit, regenerated, is the only thing that changes behaviour on the buses, and that each edit's terraform plan is exactly the resources the edit implies.

Archive, validate, compact

Every public event that reaches central is validated against the catalog schema before it is stored. A conformant event lands raw in its domain's bronze bucket; anything else is quarantined with a reason and an alarm. The compactor turns bronze into Parquet silver two hours behind bus time and re-compacts yesterday daily, so late deliveries and retries up to 24 hours still land in the right partition.

Bronze

  • NDJSON, gzip, one EventBridge envelope per line exactly as delivered
  • {source}/{detail-type}/{yyyy}/{mm}/{dd}/{hh}/ from dynamic partitioning
  • SSE-KMS with the domain CMK, Object Lock, versioning, cross-region replication in prod
  • Audit trail and analytics replay source; never mutated

Silver

  • Parquet, zstd, one file per (type, hour), overwritten atomically on re-compaction
  • Fixed envelope columns, detail as JSON, then typed d_<field> for none and indirect fields only
  • Money becomes d_<field> decimal128(18,4) plus d_<field>_currency
  • Dedupe in the compactor and again in the views: duplicates cross hour boundaries

Contract

  • ODCS v3 per public event version, generated from the schema, x-pii and ownership plus a small overlay
  • Overlay may replace description, SLAs, team, terms; append quality rules; never touch generated keys
  • datacontract test nightly against real silver; a failure is an alarm and a catalog badge
  • No contract, no reader grant: nothing is consumed outside its domain without one

PII is classified, not banned

Every schema field carries x-pii. Pseudonymous identifiers travel in clear because routing and correlation need them. Direct identifiers are encrypted by the producer with a per-subject data key, so every copy EventBridge makes holds ciphertext, and erasure is deleting the key. Special categories never enter any event.

What LocalStack proves, and what only a real account can

Spike B showed LocalStack returning green for the wrong reason on the mechanisms the design depends on most. The testing layers name those mechanisms explicitly, mark their tests, and exclude them from local runs.

L0 · Contract no infra

  • An event built by domain code validates against the catalog schema
  • Spectral and oasdiff on OpenAPI; generated clients compile against the pinned spec
  • Nothing may depend on a version past its sunset

L1 · Domain-local licensed LocalStack · ENFORCE_IAM=1

  • Own bus → forward rule → Classic stub central → subscriber-shaped rules into own queues → archive shim → own bronze → compactor → own silver
  • Two drift gates and the rule scan before any delivery test
  • Prism mocks of upstream APIs; Schemathesis on the domain's own API

L2 · Platform real AWS sandbox

  • Synthetic events from catalog schemas; an ephemeral stack per branch
  • Sandbox-only: the Custom Event Bus and RAM sharing, subscriber delivery, FIFO, dedup, replay, DLQ records, IAM and resource policies, hop limits and loop detection, Firehose partitioning and quarantine
  • Those tests carry a sandbox marker; a LocalStack divergence is xfail(strict=True) so an emulator fix surfaces

L3 · Smoke prod

  • One SmokeTest.v1 event per domain appears in its bronze bucket within the Firehose buffer
  • One GET /v1/health per API
  • Proves the forward rule, the RAM share, the Firehose subscriber and cross-account delivery on every deploy

Automated tests never see two domains together. Behavioural mismatches surface in UAT, smokes and canaries, not CI. If a test needs another domain's code, the contract is wrong.

How it gets built

Each step proves one mechanism and has an exit that can be checked. The spikes below ran first and changed the plan: the first transport decision did not survive contact with a real account.

Day one · Foundations

Catalog repo bootstrapped, decisions ratified, Terraform module library and toolchain (Terraform, Task, uv, licensed LocalStack, Node 22).

Exit: a new engineer clones two repos, runs task up && task apply && task test, calls the mock of an API that isn't built yet, and reads every convention and trade-off in under an hour.

Walking skeleton · single account, LocalStack

orders-bus and a Classic stub central; the receives[] entry rendered as a rule on the stub; archive with validation into bronze, compactor to silver, DuckDB views; the orders REST API with one command and one query; one direct field encrypted end to end. Starts from Spike C's modules and scenario-snapshot tests.

Exit: task test green for events, archive validation, dedupe and API; task query shows the event the API call produced, by correlationId.

Catalog drives the IaC

Generator emits subscribers, Firehose streams, bucket definitions, reader roles, alarms, API bodies, clients, mocks, ODCS contracts; catalog CI guardrails; a deploy-order manifest.

Exit: no hand-written rule, bucket, route, authorizer, client, alarm or role anywhere; git blame on any of them points at the generator.

Second domain, the saga, testing in isolation

payments with its own bus and bucket pair, the saga module driving authorise → capture → settle, WAF on the webhook; platform-local extracted as a versioned module; the platform_testing package; the erasure drill.

Exit: a domain proves its events, API and saga end to end with no other domain and no shared environment.

Real accounts · nonprod then prod

Platform plus one account per domain in eu-west-1; the Custom central bus shared by RAM; subscribers applied one at a time per bus in manifest order; CMKs, Object Lock, replication; DNS per domain; the replay runbook; smokes and pin promotion by PR.

Exit: the things LocalStack couldn't prove are proven continuously by smokes and drills.

Reading across domains, reconciliation, guardrails

Per-domain reader roles; DuckDB views that union deduped silver; the nightly Lambda for reconciliation, undocumented events, quarantine volume, rule and API drift, partition completeness, ROPA, decryptor review and datacontract test.

Exit: a nightly report exists and is clean; adding a domain is a catalog PR plus an account, not a platform-team project.

Accepted trade-offs, so nobody rediscovers them

  • No ordering and no exactly-once anywhere; every consumer handles duplicates and out-of-order; silver reconstructs order via aggregateVersion
  • Analytics are batch, two to three hours behind, until a named trigger fires
  • Automated tests never see two domains together
  • One catalog repo is one control plane: coherence in exchange for merge contention and generator blast radius
  • Crypto-shredding is irreversible; key deletion has an approval step and a grace period

Rules for anyone changing it

  • Change the catalog or the generator, never an account by hand; the nightly scan flags hand-made rules and routes
  • A proposal that adds a service must point at the decision row that permits it, with evidence the trigger fired
  • One synchronous hop between domains, through a generated client
  • Any dataset consumed outside its domain has an ODCS contract first
  • Read pii.md before touching a payload

Glossary

central
The platform's EventBridge Custom Event Bus: public events only, retained 30 days, shared to domain accounts by RAM.
domain bus
A domain's own EventBridge Classic bus. Every event the domain publishes lands here; one generated rule forwards public events to central.
subscriber
The Custom Event Bus's routing unit: a filter, one target, a delivery role, a retry policy and a DLQ, created in the consuming account from its receives[].
public / internal
x-visibility in the catalog. Public events are forwarded to central and archived; internal events never leave the domain account.
audience
x-audience: all or restricted; a subscriber to a restricted event is generated only with producer approval recorded in the catalog.
bronze / silver
Per-domain S3 buckets in the platform account: bronze is raw NDJSON from Firehose, silver is Parquet from the compactor.
platform-local
The versioned Terraform module a domain applies in licensed LocalStack: a Classic stub central with subscriber-shaped rules, the archive shim, the compactor and its own buckets.
saga module
The platform's in-domain stateful-process pattern. Never a cross-domain workflow.
replay flag
replay: true on re-driven events, set by the consumer's subscriber from aws:DeliveryType=REPLAY; side-effecting consumers skip them.
x-pii
The per-field classification in every schema: none, indirect, direct, special.
subject-key service
Platform module holding a data key per subject under the owning domain's CMK; erasure deletes it.
ODCS
Bitol's Open Data Contract Standard v3; one generated contract per dataset the platform serves, tested nightly.
