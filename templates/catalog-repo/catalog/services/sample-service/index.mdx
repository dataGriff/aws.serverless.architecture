## Behaviour

Commands arrive over the sample API (`POST /v1/samples`) and queries over `GET /v1/samples/{id}`; both are modelled as messages this service receives. Facts leave as events through the transactional outbox and the relay module onto `sample-bus`, and nowhere else. Each event has its own generated logical channel on that bus; the public ones route to `central-bus.<detail-type>` through the generated forward rule, the one bus-to-bus hop AWS allows. To consume another domain's public event, add a `receives[]` entry `from` this domain's `sample-sub.<detail-type>` channel; the generator creates the subscriber.
