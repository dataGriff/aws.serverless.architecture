# Catalog repository template

The starting point for the EventCatalog repo that is the platform's source of truth (ADR-017). One starter domain (`sample`) exercising every concept the generator and the checks rely on: a public event with a `direct` field, an internal event, an OpenAPI with one command and one query and their pages, an entity under `schemas/sample/`, shared value objects, a data product with its overlay, teams and `CODEOWNERS`.

It passes the whole catalog pipeline as it stands: `task all` runs the generator, the drift check, the ten checks, Spectral, the ODCS lint and the site build with a clean-tree gate.

## Lifting it into its own repository

The catalog is its own repo on day one (prompt 01). To lift this template:

1. Copy this directory to the new repository root. `catalog/` is the EventCatalog site; `Taskfile.yml`, `.mise.toml` and `.github/workflows/catalog-pr.yml` sit beside it.
2. Pin the platform tooling: set the tag in `pins.yaml` and run `task platform:checkout`. It clones the platform repository at that tag into `.platform/` (gitignored) and the Taskfile uses `.platform/platform` from then on; `task all PLATFORM=<dir>` overrides it. Inside the platform monorepo nothing is checked out and `../../platform` is used.
3. Copy `catalog/CODEOWNERS` to the repository root (GitHub reads it there).
4. Replace the placeholders listed in the platform repo's `platform.yaml` (`example.com`, `platform.example`, the org name, `editUrl`) and rename `sample` to your first domain, or run `/arch:day-one-bootstrap-catalog`, which does this against the conventions.
5. `mise install && task catalog:install && task all`.

## Layout

| Path | Hand-written or generated |
| --- | --- |
| `catalog/domains/`, `services/` (+ `openapi.yaml`), `events/*/{index.mdx,schema.json,examples/,data-product.yaml}`, `commands/`, `queries/`, `channels/<domain>-api/`, `teams/`, `data-products/`, `schemas/`, `CODEOWNERS` | hand-written |
| `catalog/events/*/odcs.yaml`, `catalog/channels/{<bus>,central-bus,<domain>-sub}.<detail-type>/` | generated by `task gen`, committed, covered by `task gen:check` (marker `x-generated: catalog-gen`) |
| `generated/local/` | generated, gitignored: rules, subscribers, routing map, validation bundles, Parquet schemas, deploy order |

Agents query the catalog through its MCP server (Scale licence, server mode) or the `llms.txt` and `schemas.txt` the static build publishes; the platform repo's `AGENTS.md` says how. The conventions are in the platform repo's `docs/architecture/conventions.md`; the worked example with two domains and cross-domain subscriptions is `spikes/A-catalog-source-of-truth/catalog/`.
